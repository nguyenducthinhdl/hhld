## Operable playbook (one-leg failure)

Runner never auto-sends flatten/hedge (miss-more). After a partial place:

1. `monitor.Inspect` classifies the TraceID (`complete` / `all_failed` / `unpaired` / `unknown_ack`).
2. Unknown legs call `GetOrder` by client order id (**never** retry `PlaceOrder` with the same cloid). Paper fake implements this; live adapters wait for P11.
3. If any leg filled and another did not, `risk.Gate.Halt(symbol)` — further Decisions miss with `halted`.
4. Operator looks up `GET /trading/forensics?trace_id=` and the flatten plan (opposite side on filled venues).
5. Operator places flatten or completing hedge (P11 live / paper fake today). That **fill** is what realizes inventory PnL — do not invent a fill for the error leg.
6. `POST /trading/halts/resume?symbol=` after exposure is closed.

Timeouts use `config.timeouts.order` as the `PlaceDecision` deadline (`unknown` status in admin when the deadline fires).

Structured logs: `HHLD_LOG_JSON=1` → `hhld.forensics` slog lines with `trace_id` / `outcome` / `halt`.
